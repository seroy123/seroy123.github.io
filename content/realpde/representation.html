Make motion, a reference state, and physical scale easy for the model to use.

Why we explored this. Early controlled runs improved when we supplied explicit changes and summaries of the observed flow. Later, an error analysis showed that windows with stronger fluctuations also had larger forecast errors and more missed uncertainty bounds. That observation motivated normalizing by local fluctuation scale, then feeding the removed statistics back into the model. The aim was to simplify the forecasting task while keeping the physical information needed to reconstruct the flow.

Make recent motion explicit

The early nnU-Net experiments added temporal differences, summaries of the current input window, and a global conditioning path. A later compact U-Net gained from five-frame sliding mean, mean absolute deviation (MAD), and standard deviation channels. These three sliding statistics remain in the final model: they expose the recent flow level and variability at each location. This is context within the observed window; T2 history adds information from earlier windows.

Last-frame conditioning and residual targets

We repeat the last observed u/v channels at every input step. Earlier frames describe motion; the last frame anchors its current position. This is already part of T1.

r = (y − xlast) / sŷ = xlast + s · r̂

y: future velocity · s: local fluctuation scale · r: residual. A zero residual predicts persistence.

Local normalization and statistical features

z = (x − μ) / s

Normalize each location by its recent mean and smoothed fluctuation scale. Feed those statistics back as channels, preserving the magnitude information.

Keep scale available inside the network

Supplying scale channels at the input was one step. In the earlier U-Net, we also used local means and scales to modulate features after each InstanceNorm layer, through SPADE. That improved every scored component and supported the hypothesis that normalization was suppressing useful magnitude information. SPADE was a successful U-Net experiment; the final SimVP model retains the input statistics and local-scale residual decoding.

Experimental evidence and implementation

Residual targets and normalization are established forecasting tools; GraphCast uses normalized residuals. We combine them with repeated last-frame channels and flow-specific local statistics.

What did removing features teach us?

Deleting the larger summary stack did not help the early model. A minimal input replaced temporal differences, summary maps and global conditioning with raw fields plus time/x/y coordinates: best local quality fell from 82.9800 to 82.4384. At a matched training budget, the full feature stack still performed better.

Removing the coordinates from that minimal model helped slightly, 82.4384 → 82.5063, while remaining below the full model. This supports testing which information is useful; it does not establish that coordinate removal would improve the full feature stack. These are historical v6 ablations.
